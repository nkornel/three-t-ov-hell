States

Every state from the brief, rendered from the same components as the main screen. These frames are frozen snapshots; the live versions are interactive above (start/stop, the ⋯ menu, the add form, the month selector and the visit list all work).

Colleague row: idle, out, out for over 30 minutes

Out = mint tint, side bar, hourglass badge, “Out” tag, live timer and a gently bobbing avatar. Over 30 minutes = red frame, striped bar, alert badge, a flashing “Over 30 min” tag and a question that prompts the operator. Start and Stop keep the same width and position so the click target never moves.

    Add colleague: refused alias

    The alias field keeps what was typed and explains the refusal in words, with an icon and a thicker red border as the non-colour cues. The counter turns red past 30 rather than silently cutting pasted text.

    Avatar picker and “all avatars taken”

    Taken avatars are greyed, hatched and carry a lock badge; the selected one gets a brass frame and a check badge. When all twenty are taken the form explains why nobody can be added and how to free an avatar.

    Leaderboard: current month vs closed months

    The current month says “in progress”, shows a blinking live marker and a dashed, outline-only “Leading” tag. Closed months switch to a double frame, a “Final” stamp with a lock, a winner banner, filled “Winner” tags with a crown, and no live elements.

    Visit list: editing, refused edits, delete confirmation

    Opened from a colleague’s ⋯ menu. Edits happen in place; a refused edit keeps the typed times, marks the offending field and explains the rule in a sentence.

    Sign-in

    The first screen. Uses the theme the system asks for, like the rest of the app.

    Save status

    Lives in the header bar, which stays dark in both themes. Saved is quiet; retrying is brass and dashed with a slowly turning icon (noticeable, not alarming); signed out is the only red state and offers the fix.

    Contrast
    
  
    WCAG 2.x ratios for every text/background pairing the design relies on. AA needs 4.5:1 for normal text, 3:1 for large text and UI component boundaries.
    
  
    

    


    
  
    Design notes
    

  
    How the six colours are used
    
  
      
    
    • Navy #111923 is the ink of the light theme and the page of the dark one. It also draws every chunky frame and hard drop shadow, which is where the 16-bit feel comes from (no blur anywhere).
      • 
    
    • Parchment #E4D5B7 is the light-theme page and the dark-theme text. Panels sit on a lighter derived parchment (#F4EBD8) so they lift off the page without needing a soft shadow.
      • 
    
    • Charcoal #23222B is the dark-theme panel surface, with a darker #191920 for sunken areas such as panel heads and the add form.
      • 
    
    • Brass #C49B4B means “honour and primary action”: the Add colleague button, the selected avatar, the leading marker and the winner. It never means running or warning.
      • 
    
    • Neon green #32CD7A means “out right now”: the Start button, running timers, the Out tag and the live marker. Nothing else is green, so a glance across the room finds who is out.
      • 
    
    • Blood red #8C2D31 means “stop or something is wrong”: the Stop button, the over-30-minute state, refused input, delete and the signed-out status. It is never decorative.
      • 
  
    

  
    What changed for contrast
    
  
      
    
    • Brass as text on light parchment is only 2.18:1, so in the light theme brass text uses a darkened #73531A (5.94:1 on panels). Brass fills keep the original shade, with navy text on top (6.85:1).
      • 
    
    • Neon green as text on parchment is 1.75:1. In the light theme timers and running totals use #0E6B3A (5.57:1); the bright green stays as a fill behind navy text (8.55:1). In the dark theme the original green is fine as text (7.6:1).
      • 
    
    • Blood red as text on charcoal is 1.90:1, so the dark theme uses #F08A86 for red text and error borders (6.50:1). The red stays as the Stop button fill with parchment text (5.72:1), and in dark mode the button gets a #F08A86 edge so its outline still reads against charcoal.
      • 
    
    • Muted text is a derived umber (#4E4A3E light, #A99E88 dark), at least 5.9:1 everywhere it appears. Disabled text is deliberately lower and is always paired with a dashed border and the not-allowed cursor.
      • 
  
    

  
    Readability from two metres
    
  
    Aliases are 22px Pixelify Sans, live timers 52px and leaderboard totals 32px in VT323. VT323 is monospaced, so digits keep the same width as they tick and nothing jiggles; font-variant-numeric: tabular-nums covers the system fallback. Both fonts come from one Google Fonts stylesheet link, with a system stack if it fails to load. Body copy stays in the system font because pixel fonts tire the eye in sentences.
    

  
    Choices made where the brief was open
    
  
      
    
    • The month selector belongs to the leaderboard only. The colleagues panel always shows today, so the operator can keep timing while looking back at September. Closed months are therefore read-only by construction; visit lists opened while a closed month is shown should open read-only too (no Edit/Delete).
      • 
    
    • Rows never reorder in the colleagues panel. They are alphabetical and stay put when someone goes out, so the button under the operator’s pointer is always the one they aimed at. Only the leaderboard re-sorts live.
      • 
    
    • Timer formats. Live timers read like a stopwatch (34:50, then 1:04:10 past an hour). Totals and longest visits always show all three units (2h 16m 02s), so columns line up.
      • 
    
    • Ties use standard competition ranking (1, 2, 3=, 3=, 5) with an “=” after the shared rank. Colleagues with no time sit under a “No time yet” divider with a dash instead of a rank.
      • 
    
    • A running visit counts immediately toward total, visit count and longest visit, which is what makes the leaderboard tick.
      • 
    
    • No avatar is preselected in the add form, so choosing one is deliberate; submitting without one shows an error on the picker.
      • 
    
    • The alias field has no hard maxlength. A counter turns red past 30 and the form refuses with an explanation, instead of silently truncating pasted text.
      • 
    
    • Archived colleagues still appear on past leaderboards, tagged “Archived” (see the March 2026 data in the month selector).
      • 
    
    • The header bar is always dark, in both themes. It gives the app a game-HUD feel and keeps the save status in a consistent place against a consistent background.
      • 
    
    • Avatars animate only while that colleague is out. Twenty idle-animating figures on a screen used all day would be tiring; motion then doubles as a “who’s out” cue from across the room. With reduced motion all avatars hold a still frame, the over-30 tag stops flashing and the retry icon stops turning; every state keeps its static cues.
      • 
    
    • Avatar descriptions (“Tricorn captain”, “Drowned helmsman”…) are placeholders used as accessible labels; swap in the real art’s descriptions.
      • 
  
    

  
    Things I’d suggest changing in the brief
    
  
      
    
    • “Session expired” conflicts with the vocabulary list, which bans “session”. The design says “Signed out” instead (“Signed out · changes waiting · Sign in again”). Likewise “rename” contains the banned “name”, so the menu says “Change alias”.
      • 
    
    • Consider auto-stopping or a one-tap fix for forgotten visits. The over-30 state shouts, but if the operator is away the visit keeps growing and decides the month. An “Ended earlier?” action in that row that opens the edit with the end time focused would make the correction one step.
      • 
    
    • Sign in with Google: the button here is a neutral placeholder. Use Google’s official button asset and logo in production; their branding rules don’t allow restyling it into the pixel look.
      • 
    
    • Pixel avatars at 40–56px: ask the illustrator to draw on a 16 or 32 pixel grid so the art scales by whole multiples (2×, 3×) with image-rendering: pixelated; odd sizes blur flat pixel art.
